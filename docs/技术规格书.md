## 修订摘要（相对原方案）

| # | 原方案 | 修正后 | 影响 |
|---|---|---|---|
| 1 | 每个平台一条 URI 模板 | 包名 + **多条 URI 降级链**，按序尝试 | 抖音、小红书等 scheme 随版本漂移，单一模板必然失效 |
| 2 | 先检测 App 是否安装，未装则提示 | **不检测，直接 startActivity + try/catch** | 绕开 Android 11+ 包可见性限制，真正实现零 `queries` 声明 |
| 3 | 未指定目标包名 | 增加 `packageName` 配置项并 `setPackage()` | 避免多 App 注册同 scheme 时弹选择器或跳错 |
| 4 | 桌面小组件内放输入框 | 改为**按钮式小组件**，点击唤起 App 内搜索态 | RemoteViews 不支持 EditText，原生做不到 |

## 勘误 v1.2（实机反馈后修正）

§3.2 把多 URI 设计成「按序降级链」，**这个描述在实践中不成立，已在 v1.2 实现中修正**。记录如下，避免以后又踩回去。

### 勘误 1：`startActivity` 成功 ≠ 到达搜索结果页

`ActivityNotFoundException` 只在「没有任何 Activity 接收该 URI」时抛出。如果 App 认 scheme、但不认 path，App 会正常启动停在首页，`startActivity` **依然成功返回**。

因此「第一条失败试第二条」这个机制，在同一 App 的多个路径之间**根本不会触发**：

| 情况 | 是否抛异常 | 能否降级 |
|---|---|---|
| App 未安装 | ✅ 抛 | 能 |
| scheme 完全无效 | ✅ 抛 | 能 |
| **scheme 有效、path 不认** | ❌ 不抛 | **不能** ← 小红书/微博的实际情况 |
| 跨 App（换了包名） | ✅ 抛 | 能 |

### 勘误 2：候选列表的真实语义

不是降级链，而是：

- **第 1 条 = 正式使用**
- 其余 = 备用 / 待人工验证

哪条真能到搜索结果页，只能靠人在设置页逐条「测试」确认一次。**不要试图用无障碍服务或截图去自动判断** —— 前者废掉零权限，后者不可靠。

### 勘误 3：新增两种能力

| 能力 | 说明 |
|---|---|
| `{keyword2}` 占位符 | 关键词编码两次。用于嵌套 query（淘宝 `h5Url`、微博 `containerid`），内层编一次、外层再编一次 |
| `altPkgs` 备用包名 | 同一产品多发行版（B 站大陆版 `tv.danmaku.bili` / 国际版 `com.bilibili.app.in`）。主包名全部失败后才试备用包名 |

### 勘误 4：淘宝协议已变更

§3.3 里的 `taobao://s.taobao.com/search?q=` 在多数版本已失效，改用官方 `tbopen://` 协议（把 H5 地址整个编码后塞进 `h5Url`）。详见 README §4。

### 勘误 5：各平台协议差异

| | 抖音 | 小红书 | 微博 |
|---|---|---|---|
| scheme | `snssdk1128` | `xhsdiscover` | `sinaweibo` |
| 搜索路径 | `/search` | `/search/result` | `/searchall` |
| 关键词承载 | `?keyword=` 扁平 | `?keyword=` 扁平 | 嵌套在 `containerid` 的 query string 里 |
| 编码次数 | 1 | 1 | 可能需 2 |

## 一、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Kotlin 2.0 | 官方主推，协程原生支持 |
| UI | Jetpack Compose + Material 3 | 两页极简界面，Compose 代码量最小 |
| 架构 | 单 Activity + Compose Navigation（2 个 destination） | 规模不足以引入多模块 |

## 二、权限与安全边界（硬约束）

### 2.1 权限清单：零权限

`AndroidManifest.xml` 中**不声明任何 `<uses-permission>`**。

| 权限 | 是否声明 | 说明 |
|---|---|---|
| `INTERNET` | ❌ | **本方案的技术红线基石**。不声明则进程物理上无法建立网络连接，任何误引入的 SDK 都失效 |
| `ACCESS_NETWORK_STATE` | ❌ | 无需联网 |
| `QUERY_ALL_PACKAGES` | ❌ | 用 try/catch 替代，见 §3.2 |
| `READ/WRITE_EXTERNAL_STORAGE` | ❌ | 历史存 App 私有目录 |
| `POST_NOTIFICATIONS` | ❌ | 无通知 |
| `VIBRATE` | ❌ | 点击反馈用 Compose ripple，不振动 |

### 2.2 为什么不需要 `<queries>`

Android 11（API 30）起引入**包可见性（Package Visibility）**，但限制的只是**查询类 API**：

- 受限：`getPackageInfo()`、`queryIntentActivities()`、`resolveActivity()`、`getInstalledPackages()`
- **不受限：`startActivity()`** —— 隐式 Intent 直接启动不受包可见性约束

因此「先查再跳」不成立，但「直接跳、失败捕获」完全成立：

```kotlin
// 不需要任何权限、不需要 queries
try {
    context.startActivity(intent)
} catch (e: ActivityNotFoundException) {
    // 未安装 或 scheme 无效
}
```

**代价**：无法在 UI 上把「未安装的平台」置灰。自用版不需要这个能力，接受。

> ⚠️ 若将来某个需求要求「未安装置灰」，只能在 manifest 里为每个包名加 `<queries><package android:name="..."/></queries>`，且每新增平台都要改 manifest —— 与「配置化增删平台」直接冲突。所以本版坚决不做。

### 2.3 网络红线的双重保障

1. **Manifest 不声明 `INTERNET`**（物理隔离）
2. 代码层不引入任何网络库

第 1 条是充分条件，第 2 条是防御性冗余。评审验收时只需检查 manifest 有无 `uses-permission`。

### 2.4 数据不出设备

- 无云端、无账号、无备份
- 建议在 manifest 加 `android:allowBackup="false"`，避免历史被系统备份到云

## 三、核心模块：跳转引擎（JumpEngine）

这是整个 App 唯一有技术含量的部分，其余都是表单。

### 3.1 数据结构

```kotlin
@Serializable
data class Platform(
    val id: String,              // UUID，稳定主键
    val name: String,            // 显示名，如「小红书」
    val packageName: String?,    // 目标包名；null = 不限定，交给系统分发
    val uris: List<String>,      // 有序降级链，含 {keyword} 占位符
    val enabled: Boolean = true,
    val isBuiltin: Boolean = false,
    val note: String = ""        // 备注，如「v8.x 实测可用」
)
```

### 3.2 跳转算法

```
输入：platform, rawKeyword
输出：Success(已启动) | Fail(原因)

1. kw := rawKeyword.trim()
2. if kw.isEmpty() → Fail(EMPTY_KEYWORD)
3. if kw.length > 200 → kw := kw.take(200)   // 见 §3.4
4. encoded := Uri.encode(kw)                // 空格→%20，非+号
5. for uriTemplate in platform.uris:
       a. if uriTemplate 不含 "{keyword}" → continue（配置错误，跳过）
       b. uriStr := uriTemplate.replace("{keyword}", encoded)
       c. intent := Intent(ACTION_VIEW, Uri.parse(uriStr))
       d. if platform.packageName != null:
              intent.setPackage(platform.packageName)
          intent.addFlags(FLAG_ACTIVITY_NEW_TASK)
       e. try { context.startActivity(intent); return Success }
          catch (ActivityNotFoundException) → continue（试下一条）
          catch (SecurityException)        → continue
          catch (Exception)                → continue
6. return Fail(ALL_URIS_FAILED)
```

**关键点**：

- **逐条降级**：抖音 `snssdk1128://search` 失败后自动试 `aweme://search`。平台更新 scheme 时，只要用户填了新模板，旧模板留着也无害。
- **`setPackage` 的作用**：限定只有该包能响应。副作用是——若该包未安装，即使有其他 App 能处理同 scheme，也会抛 `ActivityNotFoundException`，从而走降级链或错误提示，**不会误跳**。这正是我们要的。
- **`FLAG_ACTIVITY_NEW_TASK`**：从非 Activity context（如 ViewModel）启动时必需；从 Activity context 启动加了也无害，统一加。
- **失败后不回滚 UI**：跳转失败弹提示，关键词和平台选择保持不变，用户改完模板可直接重试。

### 3.3 内置平台 URI 表

> 置信度：★★★ = 社区广泛验证；★★ = 有报告可用但版本相关；★ = 不确定，需实测。
> **所有模板在首次使用前必须按 §11 的真机实测清单验证。**

| 平台 | 包名 | URI 降级链 | 置信度 |
|---|---|---|---|
| 小红书 | `com.xingin.xhs` | ① `xhsdiscover://search?keyword={keyword}`<br>② `xhsdiscover://search/result?keyword={keyword}`<br>③ `xhsdiscover://rn/search?keyword={keyword}` | ★★ |
| 抖音 | `com.ss.android.ugc.aweme` | ① `snssdk1128://search?keyword={keyword}`<br>② `snssdk1128://search/discover?keyword={keyword}`<br>③ `aweme://search?keyword={keyword}` | ★★ |
| 哔哩哔哩 | `tv.danmaku.bili` | ① `bilibili://search?keyword={keyword}` | ★★★ |
| 知乎 | `com.zhihu.android` | ① `zhihu://search?q={keyword}`<br>② `zhihu://search?type=content&q={keyword}` | ★★ |
| 百度 | `com.baidu.searchbox` | ① `baiduboxapp://s?word={keyword}` | ★ |
| 微博 | `com.sina.weibo` | ① `sinaweibo://searchall?containerid=100103type%3D1%26q%3D{keyword}` | ★ |
| 淘宝 | `com.taobao.taobao` | ① `taobao://s.taobao.com/search?q={keyword}` | ★★ |

**百度特例**：`baiduboxapp://` 极不稳定。若用户希望更强兜底，可把 `packageName` 设为 `null`、URI 设为 `https://www.baidu.com/s?wd={keyword}`，由系统走 App Links 或浏览器分发。**注意**：这不违反本项目红线（本 App 自己不联网），但会打开一个带信息流的浏览器页，与「防分心」初衷有限冲突 —— 默认不配这条，留作用户自选。

### 3.4 关键词预处理细则

| 场景 | 处理 |
|---|---|
| 前后空格 | `trim()` |
| 空 / 纯空格 | 搜索按钮 `enabled = false`，不发 Intent |
| 长度上限 | **200 字符**（Unicode 码点计）。超出截断并在 UI 提示「已截断」 |
| 特殊字符 `& # ? / %` | `Uri.encode()` 自动编码，无需特殊处理 |
| 空格 | `Uri.encode` 编为 `%20`（**不是 `+`**）。部分 App 不认 `+`，这是必须用 `Uri.encode` 而非 `URLEncoder` 的原因 |
| 中文 | `Uri.encode` 编为 UTF-8 百分号序列，正确 |
| Emoji / 代理对 | 按码点截断，避免切坏代理对（`String.take` 按 char 截会切坏，需按 codePoint 截） |

**为什么是 200**：主流 scheme 处理无明确上限，但 Intent URI 超过约 2KB 时部分 ROM 的 Binder 传输会异常。200 字符中文编码后约 600~900 字节，安全。

### 3.5 代码骨架

```kotlin
sealed interface JumpResult {
    data object Success : JumpResult
    data object EmptyKeyword : JumpResult
    data object AllUrisFailed : JumpResult
    data class UnknownError(val msg: String) : JumpResult
}

class JumpEngine(private val context: Context) {

    fun jump(platform: Platform, rawKeyword: String): JumpResult {
        val kw = rawKeyword.trim()
        if (kw.isEmpty()) return JumpResult.EmptyKeyword
        val clipped = kw.takeByCodePoints(200)
        val encoded = Uri.encode(clipped)

        for (template in platform.uris) {
            if (!template.contains("{keyword}")) continue
            val uriStr = template.replace("{keyword}", encoded)
            val intent = Intent(Intent.ACTION_VIEW, Uri.parse(uriStr)).apply {
                platform.packageName?.let { setPackage(it) }
                addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
            }
            try {
                context.startActivity(intent)
                return JumpResult.Success
            } catch (e: ActivityNotFoundException) {
                continue
            } catch (e: SecurityException) {
                continue
            } catch (e: Exception) {
                continue
            }
        }
        return JumpResult.AllUrisFailed
    }
}

private fun String.takeByCodePoints(max: Int): String {
    if (codePointCount(0, length) <= max) return this
    val end = offsetByCodePoints(0, max)
    return substring(0, end)
}
```

## 四、数据层

### 4.1 数据模型

```kotlin
@Serializable
data class HistoryItem(
    val keyword: String,
    val platformId: String,
    val platformName: String,   // 冗余存名字，平台被删后历史仍可读
    val timestamp: Long
)

@Serializable
data class AppSettings(
    val lastPlatformId: String? = null,
    val rememberLastPlatform: Boolean = true,
    val historyEnabled: Boolean = true
)
```

### 4.2 存储选型对比

| 方案 | 取舍 | 结论 |
|---|---|---|
| Room | 需要 KSP 注解处理，构建变慢，写 3 个 Entity + DAO + 迁移 | ❌ 规模不匹配 |
| DataStore + JSON（kotlinx.serialization） | 每次写入全量序列化，但数据量小（平台 <20 条、历史 <500 条） | ✅ **推荐** |
| SharedPreferences | 最简，但无协程/Flow 支持，易 ANR | ❌ 技术债 |

**结论**：两个 DataStore 实例。

| 键 | 类型 | 内容 |
|---|---|---|
| `platforms` | `String`(JSON) | `List<Platform>` 全量 |
| `history` | `String`(JSON) | `List<HistoryItem>`，**倒序**，上限 200 条 |
| `settings` | `String`(JSON) | `AppSettings` |
| `schema_version` | `Int` | 数据迁移用，出问题直接重置 |

**文件位置**：`/data/data/<pkg>/datastore/*.preferences_pb`——App 私有目录，卸载自动清除，无需任何存储权限。

### 4.3 首次启动初始化

`platforms` 为空时写入 §3.3 的 7 个内置平台（`isBuiltin = true`），`lastPlatformId` 设为第一个启用的平台。

**内置平台可编辑、可删除、可禁用**，不做「恢复默认」按钮——自用版，删了就删了，需要时重装。

### 4.4 历史记录规则

| 规则 | 说明 |
|---|---|
| 写入时机 | **跳转成功后**才写（失败不记录，避免污染） |
| 去重 | 同 `keyword + platformId` 已有则更新时间戳并移到最前 |
| 上限 | 200 条，超出丢尾部 |
| 开关 | `historyEnabled = false` 时既不写也不显示，已存数据**不删除**（关掉再打开还在） |
| 清空 | 一键清空，二次确认 |
| 展示 | 最多显示 20 条，超出给「查看全部」 |

**规格细节**：

| 元素 | 规格 |
|---|---|
| 输入框 | `singleLine = true`，`imeAction = Search`，键盘回车等同点搜索 |

| 右侧清除 | 输入框内 `trailingIcon` 的 ×，仅在有内容时出现 |
| 历史折叠 | 默认收起。展开后 `LazyColumn`，每项点击 → 回填关键词 + 切到对应平台（不自动跳转，用户确认后再点搜索） |

- ❌ 任何 `LaunchedEffect` 里发网络请求
- ❌ 任何图片加载库（Coil/Glide）
- ❌ WebView
- ❌ 下拉刷新组件
- ❌ 任何形如「热门」「推荐」「猜你想搜」的文案或逻辑

#### 5.2.1 平台管理

列表页：每个平台一行，右侧 `Switch` 控制启用，点击行进入编辑页。

编辑页字段：

| 字段 | 控件 | 校验 |
|---|---|---|
| 平台名称 | `OutlinedTextField` | 非空，≤ 12 字 |
| 包名 | `OutlinedTextField` | 非空或全空（空 = 交给系统）；格式 `a.b.c` |

| 删除平台 | 底部 `TextButton` 红色 | 二次确认 |

交互：

- 右上「保存」：校验通过才落盘，返回列表
- 右上「测试」按钮：使用当前输入框的 `{keyword}` 替换成 `测试`，按 §3.2 算法试跳一次，Toast 报结果——**这个按钮价值极高**，让用户不用来回切到首页验证模板是否有效
- 新增平台：列表页 `FAB(+)`

#### 5.2.2 搜索历史

- `Switch`：开启本地记录
- 列表：全部历史（最多 200 条），滑动删除单条
- 底部「清空全部历史」，红色，二次确认

#### 5.2.3 桌面快捷方式

**技术实现**：`ShortcutManagerCompat.requestPinShortcut()`

```kotlin
val shortcut = ShortcutInfoCompat.Builder(context, "search")
    .setShortLabel("直搜")
    .setIcon(IconCompat.createWithResource(context, R.drawable.ic_search))
    .setIntent(Intent(context, MainActivity::class.java)
        .setAction(Intent.ACTION_VIEW)
        .putExtra("focus_search", true))
    .build()
ShortcutManagerCompat.requestPinShortcut(context, shortcut, null)
```

- 点击后系统弹「是否添加到主屏幕」，用户确认
- **不支持 requestPinShortcut 的启动器**（部分国产 ROM）：降级为 `Toast` 提示「当前桌面不支持，请手动从应用列表拖出」
- 无需任何权限

#### 5.2.4 关于

静态文本：App 名称、版本号（`BuildConfig.VERSION_NAME`）、构建日期、一行备注「本工具不联网，仅做搜索跳转」。可留一个「自用备注」多行文本，存在 DataStore。

## 六、交互时序

### 6.1 主流程

```
用户点击 App 图标
  → MainActivity.onCreate
  → 读 DataStore（platforms / settings）
  → Compose 渲染 SearchScreen
  → LaunchedEffect: 100ms 后 requestFocus，弹键盘
  → 用户输入关键词（每字符更新 state）
  → 用户点平台 Chip（更新 selectedPlatformId）
  → 用户点【搜索】
  → 校验：非空 + 平台已选
  → JumpEngine.jump()
      → 构造 Intent → startActivity
      → 成功：写历史（若开启）→ 记 lastPlatformId（若勾选）→ 落盘
      → App 进入后台（系统自动）
  → 用户后续操作在目标 App 内，本工具不介入
```

**返回本 App 时的状态**：保留上次的关键词，但**输入框不自动全选**（避免用户误覆盖）；焦点仍在输入框但**不自动弹键盘**（避免一回来就遮挡）。这是刻意的——反复弹键盘很烦。

### 6.2 从桌面快捷方式进入

`intent.getBooleanExtra("focus_search", false) == true` → 立即聚焦并弹键盘（此时用户意图明确就是要搜）。

### 6.3 从分享进入（扩展 2，可选）

其他 App 分享文字 → `ACTION_SEND` + `text/plain` → `MainActivity` 读 `EXTRA_TEXT` → 填入输入框（取前 200 字符）→ 聚焦 → **不自动跳转**，让用户选平台。

## 七、异常处理矩阵

| # | 场景 | 检测方式 | 处理 | 文案 |
|---|---|---|---|---|
| 1 | 关键词为空 | `trim().isEmpty()` | 按钮 `enabled=false`，点击无响应 | 输入框 placeholder：「输入关键词后开始搜索」 |
| 2 | 未安装目标 App | `ActivityNotFoundException`（全部 URIs 失败） | `AlertDialog` | 「未检测到「小红书」，无法跳转。你可以去设置里修改跳转规则，或检查是否已安装。」 |
| 3 | URI 全部失效 | 同 #2（无法区分） | 同上，但文案侧重模板 | 「「小红书」跳转失败。可能是 App 更新后链接规则变化，请到设置 → 平台管理修改 URI 模板。」 |
| 4 | 单条 URI 含 `{keyword}` 配置错误 | 编辑页保存时校验 | 阻止保存 | 「第 N 行缺少 {keyword} 占位符」 |
| 5 | 超长关键词 | `codePointCount > 200` | 静默截断 + Snackbar | 「关键词过长，已截断至 200 字」 |
| 6 | 特殊字符 | 无（自动编码） | 正常处理 | — |
| 7 | 数据解析失败（JSON 损坏） | `SerializationException` | 重置为内置默认平台，保留 history 不动 | 「配置已重置」 |
| 8 | 目标 App 存在但拒绝响应 | `SecurityException` | 走降级链，全失败按 #2 | 同 #2 |
| 9 | 全部平台被禁用 | `enabled == true` 的列表为空 | 首页显示空态 | 「所有平台已禁用，请到设置中启用」 |

**#2 与 #3 的区分难题**：`ActivityNotFoundException` 无法区分「未安装」和「scheme 无效」。统一文案需兼顾两种可能，故措辞同时提及安装和规则。不做额外检测（那需要 queries，见 §2.2）。

**错误提示形态**：使用 `AlertDialog` 而非 Toast——Toast 在部分 ROM 上会因 App 切后台而丢失，弹窗更可靠。

## 八、可选扩展的技术约束

### 8.1 桌面小组件（AppWidget）

**硬约束**：`RemoteViews` 支持 `TextView`、`Button`、`ImageView`、`ProgressBar` 等，**不支持 `EditText`**。所以「桌面上直接输入关键词」原生做不到（除非用 `Activity` 伪装成小组件，那是 hack，不做）。

**可行方案**：按钮式小组件

```
┌──────────────┐
│   🔍 直搜     │  ← 单个 Button，点击启动 MainActivity + focus_search=true
└──────────────┘
```

- 尺寸：2×1
- 实现：`AppWidgetProvider` + `PendingIntent.getActivity()`
- 成本：约 100 行（含 XML 布局 + 配置 Activity 可选）
- 结论：**建议做**，它把「打开 App 再点搜索框」压成一次点击

### 8.2 快捷分享（ACTION_SEND）

```xml
<intent-filter>
    <action android:name="android.intent.action.SEND" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:mimeType="text/plain" />
</intent-filter>
```

- 无需权限
- 注意：`EXTRA_TEXT` 可能含 URL 或长文本，按 §3.4 截断
- 成本：约 30 行
- 结论：**建议做**

### 8.3 预设关键词模板

- 数据结构：`List<Preset>`（`id`, `label`, `keyword`），存 DataStore
- UI 位置：首页平台 Chip 下方新增一行「预设」Chip，点击回填（不跳转）
- 风险：容易演变成「书签栏」，与极简初衷有张力
- 结论：**v1.1 再做**，v1 先不加

### 8.4 明确不做的扩展

| 想法 | 否决理由 |
|---|---|
| 搜索词联想/补全 | 必然需要联网或本地词库，前者违反红线，后者是伪需求 |
| 多平台同时搜索（一次开 5 个 App） | 体验灾难，且会被系统限制 |
| 搜索结果聚合 | 违反「不渲染第三方内容」红线 |
| 云端同步配置 | 违反「不上云」红线 |
| 桌面悬浮球 | 需要 `SYSTEM_ALERT_WINDOW` 权限，与零权限冲突 |
